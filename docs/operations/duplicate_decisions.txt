# Duplicate pairs a person has looked at and decided to KEEP AS TWO ROWS.
#
# WHY THIS FILE EXISTS
# The detectors are working correctly when they surface these. Two co-located expos from one
# organiser, and one event running both a call for speakers and a call for exhibitors, look
# exactly like one event held twice - same city, same dates, nearly the same name. Nothing in
# the data distinguishes them; only a person reading the two websites can.
#
# Without a record of that reading, every run re-reports them as open findings, the report
# never comes back clean, and the lesson of 2026-09-15 applies: A CHECK THAT CANNOT TELL A
# REASONED DECISION FROM A FAULT TEACHES PEOPLE TO STOP RUNNING IT.
#
# So a decision is DECLARED here rather than remembered on a command line. The pair is still
# printed on every run, under DECIDED, with its reason and its date - visible and reviewable,
# just not counted as work outstanding. That is the same treatment `held_rows.txt` gives a row
# kept without a counterpart (contract 2.1): declared, never hidden.
#
# FORMAT   one decision per line, `#` comments and blank lines ignored
#     YYYY-MM-DD <event_id> <event_id> [<event_id>...] | who decided | why
#
# A decision settles the EXACT SET of rows it names. If a third row later joins the group, the
# set no longer matches and the group is reported again - new evidence reopens the question,
# which is the behaviour we want.
#
# TO REVERSE ONE, delete its line. Nothing else reads it.
