# Tooling index - what already exists, and when to use it

**Read this before writing any new tooling for the CFP pipeline.**

This file exists because on 2026-08-05/06 a parallel delivery validator and a parallel
citation checker were built from scratch while `accept_delivery.py` and
`recheck_dead_links.py` already did the job - better. The information needed to prevent that
was available, but answering *"does a tool already exist for this?"* meant reading twenty
filenames and guessing. One page fixes that.

If you are about to write something that validates, fetches, verifies, repairs or reports,
check this list first. If it is not here, add it here when you build it.

---

## The three-stage shape

Work on a market moves through three stages. Use the tool that belongs to the stage.

| Stage | Question it answers | Tool |
|---|---|---|
| **Before** research | Is this input worth spending requests on? | `preflight_market.py` * |
| **During** research | Is this market finished, and did anything get lost? | `validate_market_output.py` * |
| **Before** shipping or loading | Does this delivery meet the contract? | **`scripts/accept_delivery.py`** |
| **After** any import or migration | Does the DATABASE still hold what was delivered? | **`scripts/check_invariants.py`** |
| **Before** anything leaves the building | Can we PROVE this to someone who disagrees? | **`scripts/audit_evidence.py`** |

`accept_delivery.py` and `check_invariants.py` are not duplicates: the first judges a
DELIVERY against the contract, the second judges the DATABASE against the delivery. A file
can be perfectly acceptable and still be imported into a database that quietly lost four
rows - which is exactly what happened on 2026-08-08.

`*` lives in the **upstream working area**, a folder outside this repo. Its path is
machine-specific - see the local `CLAUDE.md` rather than hard-coding it here.

**`accept_delivery.py` is the only authoritative gate.** Nothing else decides whether a
delivery is acceptable. If a check belongs to the contract, it belongs in that script - do
not add a second opinion elsewhere.

Never touches `event_id`. | 67 of 392 rows carried an edition disagreeing with their start date, and because `event_id()` builds the key from edition, two duplicate records were created by it. **A key is a name, not a fact** - the fix is to stop reading meaning out of the key, not to rewrite 67 keys. Showing the model the regex answer would buy agreement bias, not confirmation. ## Fetching - the escalation ladder

Defined in `src/cfp_monitor/coverage.py` as `PATH_ORDER`:

```
crawl4ai  ->  playwright-fallback  ->  cdp  ->  manual-antibot  ->  unresolved
```

| Rung | What it is |
|---|---|
| `crawl4ai` | Headless, cheapest. |
| `playwright-fallback` | Our own Playwright. **Runs HEADED by default** (`CFP_FALLBACK_HEADLESS=false`) because headless gets 403'd. A visible window means a CAPTCHA is solvable by hand. |
| `cdp` | Attaches to a REAL Chrome on port 9222, dedicated profile `~/cfp-cdp-profile`. `ensure_cdp()` auto-launches it. Disconnects rather than closes. For hard anti-bot domains. |
| `manual-antibot` | Formally recorded outcome: manual / signed-in needed. Not a failure. |
| `unresolved` | Nothing worked. |

Never re-implement a rung of this ladder. `src/cfp_monitor/cdp.py` and `fetch.py` own it.
Running only the first rung and declaring a link dead is the specific mistake this row exists
to prevent.

## Delivery handling

| Script | What it does |
|---|---|
| `scripts/import_grounding.py` | Import a delivery into `grounding_facts`. |
| `scripts/import_awards.py` | **Import an ACCEPTED awards delivery into `award_grounding_facts` + `award_markets`.** The awards sibling of `import_grounding.py`, sharing no code path with it - only the rules layer (`grounding.event_id`, `storage.normalize_key`), because a rule copied is a rule that drifts. **The gate decides, enforceably:** it refuses without the JSON `accept_delivery.py` wrote, refuses a JSON naming a different file, and refuses if any check failed. **Mints OUR canonical id and keeps upstream's in `upstream_event_id`** (5.4) - 97 of 119 differ; minting at first import is the only moment it is safe, since R24/R25 freeze a key thereafter. Rows are EXCLUDED and named, never dropped silently: `OPPORTUNITY_TYPE` that is not `Awards` (the awards file carries a few Speaking/Registration rows), and rows the seed labels `DUP_OF`. **A `DUP_OF` naming a customer-sheet coordinate (`Utility Global:46`) is a cross-reference, NOT a deletion** - honouring it as one silently dropped 7 real rows including a citation withdrawn by agreement the same day, so a label counts only when it names a row in the delivery. `award_markets.award_key` is the canonical `event_id`, deliberately unlike `conference_markets`, which keys by host: cloud-awards.com runs four programmes with four deadlines and a host key cannot say which belongs to which market. | `scripts/link_check_awards.py` | **Link-checks the awards rows into the SAME `link_checks` table the customer page reads.** Exists because `weekly_verify.py` collects with `select * from grounding_facts` - conference rows only - so no awards link had ever been checked, which is why the awards page renders an em dash and "not yet checked" rather than a zero. **`link_checks` is keyed by URL, not by event, so it was already domain-neutral**; the conference scoping lived entirely in which rows got harvested, and a second table would have split one fact across two places. Same four `CUSTOMER_FACING` fields, named here rather than imported so a change to the conference list cannot silently change this one. Fast pass, then a real browser for anything returning 404/410 - **a plain-HTTP 404 is never sufficient evidence a page is gone**. Report-only by default; `--apply` backs up first. `--no-browser` reports fast-pass results explicitly UNCONFIRMED. Tests: `tests/test_link_check_awards.py`. |
| `scripts/repair_delivery.py` | Rebuild a delivery broken by unquoted commas. Refuses to write unless every rebuilt row validates on six independently-shaped fields. **A repaired file still fails the gate** - upstream must fix its writer. |
| `scripts/delivery_loop.py` | **Closes a delivery's hand-back loop without a person carrying messages.** Each round: gate (`--json`) -> `mechanical_repairs` -> gate -> structured findings per row -> `Markets/answer_findings.py` (Gemini, grounded, standing rules attached) -> every answer VERIFIED against the live page before use -> gate. Stops on ACCEPTED, no progress, `--max-rounds` (2), or a quota error. **Applies only citations and links** (v2.0.1 section 3 gives those to upstream): a URL must resolve, be admissible and be a real page; evidence must not be a homepage and must state the row's deadline; a quote that is not the page's own text is replaced by OUR extraction (section 3 note). **A proposed change to a claim - a date, a status, event dates - is never applied**; it is checked and listed in SUMMARY.md for a person. Gate failures map to a row only when the truncated name matches exactly one row; the rest go to a person. Tests: `tests/test_delivery_loop.py`, `Markets/test_answer_findings.py`. |
| `Markets/answer_findings.py` (upstream working area) | **Upstream's side of the automatic hand-back.** One grounded Gemini request per row with findings, capped by `--max-requests`; exit 3 on quota, like the Saturday run. Answers only `replace` (link fields), `none_public` or `propose_change`, validated for shape; truth is downstream's to check. Never sends NOTES. `--dry-run` prints prompts and the request count. |
| `scripts/mechanical_repairs.py` | **Contract v2.4: repairs how a delivery WRITES its claims, never what it claims** - run it when the gate rejects, before sending anything back. (A) re-copies a quote from the already-cited page when check 3 says "paraphrase, date IS on page"; (B) with `--prior`, carries upstream's replacement URL to every field still holding the identical dead link; (C) plain text in prose fields; (D) R1-withdraws a citation dead in a plain fetch AND a real browser. **Declines rather than guesses:** a deadline appearing twice on the page, a span holding another date, a serialised list, a withdrawal that would break check 4, a link upstream changed this delivery, a bracketed value on a projected row (R4's own projection form) - each is reported as still needing upstream. Report-only by default; `--apply` writes `<delivery>.repaired.csv` and `<delivery>.repairs.md` (the log for upstream) and re-runs `accept_delivery.py` on the repaired file - it is not a second gate. **Point a replay at `--ledger <scratch>`**, or next cycle's genuine repairs look like repeats. Not to be confused with `repair_delivery.py` (unquoted-comma CSVs). Tests: `tests/test_mechanical_repairs.py`. |
| `scripts/join_parts.py` | Join a delivery pasted as numbered chat parts. |
| `scripts/apply_resolutions.py` | Apply upstream dispute resolutions. **`--citations <csv>` is the MERGE GUARD** for a citation-repair round: a blank never overwrites a populated field; a proposed citation must pass OUR fetch and have its quote on the page; a failed proposal leaves the old one standing; every accepted change is logged old -> new. Reports by default, writes with `--apply`. |
| `Markets/apply_row_patch.py` (upstream working area) | **Merges a row-level patch into a delivery that is not yet imported.** Same guards as `apply_resolutions.py --citations`, for the case where the rows are still a file: `apply_resolutions.py` needs a database and `apply_recut_citations.py` is citation-only. Updates only - an `EVENT_ID` not already in the delivery is an error, never an insert (5.4). **A blank in a patch is ambiguous** - "not part of this patch" or "empty this on purpose" - so blanks are ignored by default and a deliberate clear is declared per row with `--withdraw <EVENT_ID>`, which may empty `DEADLINE_EVIDENCE_URL` and `DEADLINE_QUOTE` and nothing else (R1: the deadline itself never travels with the citation). ## The rules layer - decisions, not scripts

These are libraries, not commands. Everything that has to make the same judgement calls them
rather than re-deriving; that is what stops a rule drifting between the gate, the weekly job and
the customer page.

| Module | What it decides | Notes |
|---|---|---|
| `src/cfp_monitor/rules.py` | May we withdraw this citation? Is this source admissible (R22)? Which round is THE deadline (R23)? May the stamp advance? Is this link dead? | Pure functions, each returning a REASON, never a bare bool. `withdrawal_changes` takes `fetched` with **no default** so a caller cannot skip the decision - that omission cost four rows on 2026-08-29. |
| `src/cfp_monitor/lifecycle.py` | Where a conference sits in its life, and what follows: edition state (R13), call state, urgency, what WE do next and what it costs. | **Specified in `DECISION-TREE.md`** - if the two disagree, the doc wins. `overrides(stored)` decides whether a derived value may replace the file's: only a DATE ON THE ROW qualifies, never an inference from absence or a choice between two true words. |
| `src/cfp_monitor/sitewalk.py` | Which links on a page are worth following. | One site-walker, was four. Relevance **ranks, never filters** - a filter throws away the thing you were looking for and leaves no trace. |
| `src/cfp_monitor/clients.py` | The client layer: which conferences a client tracks, and their own status against each. | Per-client values live here and **never** on `conferences`, whose columns are shared and single-valued. `conferences.status_details` is 349/373 filled with OUR crawl text under the same name as theirs. |
| `src/cfp_monitor/sheet_diff.py` | What the customer changed week over week, and where their silence costs something. | Only customer-owned fields count as them acting; a deadline we corrected is us. Untouched rows are COUNTED, not listed - except where the deadline is inside 30 days and nothing is settled. |

## Rules that keep this from rotting

1. **Check this file before building.** If something close exists, extend it.
2. **Add your tool here the moment you build it**, with the stage it belongs to.
3. **One gate.** Contract criteria go in `accept_delivery.py`, nowhere else.
4. **Never widen a schema without checking `EXPECTED_COLS`.** Adding `FORMAT` as column 36
   silently made the gate reject every delivery on check 1 while a parallel validator
   reported PASS.
