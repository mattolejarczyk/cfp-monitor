## The operating model (agreed with the operator, 2026-10-05)
- The operator wants to be OUT of the loop. Work goes through the control list in large chunks (waves). A BUILDER sub-agent implements in an isolated git worktree and branch; YOU (the reviewer, Claude) verify, apply anything live, merge, and mark actions verified. The builder never grades itself and never verifies. Only items marked "Needs you" wait for the operator; surface them in one short digest per wave.
- Autonomy tiers. Builder alone: code, tests, docs in its worktree, sandbox rehearsals, read-only network, cheap-model calls (about 0.30 USD a run, about 1 USD a wave, no new keys). Reviewer only: anything touching the live database (`%LOCALAPPDATA%/CFP-Monitor/cfp_monitor.db`), `Markets/*` (approved files, input lists, scripts), the Friday/Saturday job scripts, always with a backup, a rehearsal and a log line. Operator only: anything sent outside (notes to upstream are drafted for him to send), rulings about what is true of an event, spend beyond the caps, new keys, scheduled-task changes, customer-facing wording, contract questions.
- Decisions already made by the operator: a fact a page proves AND that agrees with our value counts as confirmed for scoring the grounded call, never the reader (ACT-04); status-only verifications read "Call confirmed, date not confirmed on page" (ACT-48, applied); the autonomy tiers and caps above.
